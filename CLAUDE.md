# CLAUDE.md — orientation for agents

Start here, then read `ARCHITECTURE.md` for depth. This file is the 60-second map
of how the site is built *today*.

## What this is

A static **Jekyll** site for a fantasy-football league ("The League",
noloveintheleague.com), hosted on GitHub Pages from the `docs/` folder. League
data is hand-edited / imported YAML, compiled to `docs/_data/*.yml` by small
Python scripts, and rendered by Jekyll.

## The three layers (data flows one way)

```
1. IMPORT   data/*.yml            hand-edited + written by the ESPN importer
                │  scripts/build.py
2. BUILD    docs/_data/*.yml      generated — Python computes every value
                │  Jekyll
3. RENDER   docs/ pages+includes  Liquid templates, no computation
```

- **`data/`** is the source of truth (`seasons/<year>.yml`, `franchises.yml`,
  `overrides.yml`, `season_notes.yml`, `settings.yml`). Edit here.
- **`scripts/`** reads `data/`, computes everything (records, standings, colors,
  tags), and writes `docs/_data/*.yml`. Pure logic lives in **`scripts/lib/`**
  with tests; the `generate_*.py` files are thin.
- **`docs/`** is presentation only. Includes are organized by role:
  `_includes/bits/` (leaf primitives), `_includes/tables/` (shared tables),
  `_includes/sections/` (full-width page blocks). A page-type's layout lives in
  one section template (e.g. `sections/season_detail.html` composes
  `sections/season/*`), so restyling a page type is one file, not many.

## Golden rules

- **Never hand-edit `docs/_data/*.yml`** — regenerated by `build.py`.
- **New computation goes in `scripts/lib/` with a test**, never inline in a
  generator or a template.
- **Templates stay presentational**; all values are precomputed in Python.
- Per-owner (`docs/teams/<id>.md`) and per-season (`docs/seasons/<year>.md`)
  pages are **scaffolded once, then hand-editable** — the build never overwrites
  an existing one. Delete to regenerate.
- Franchise `id`s are stable and lowercase; add `aliases`, never rename an `id`.

## Build & test

```
python scripts/build.py               # regenerate docs/_data/*.yml
python scripts/tests/test_lib.py      # or: python -m pytest scripts/tests
cd docs && bundle exec jekyll serve   # preview locally (needs Ruby+Bundler)
```

## The ESPN CLI (import-time only — read this before touching data flow)

Raw data comes from **`the-league-espn-api`** (repo `espn-fantasy-cli`), but it
is an **import-time dependency only**: `scripts/import_espn.py` pulls a season
into `data/seasons/*.yml`, and that's it. `build.py` does **not** call the CLI —
the site builds fine without it installed, computing its own stats from the
stored YAML and layering league-specific overrides (co-champions, "meaningless"
games, Shiva/Sacko naming, season-lifecycle gating).

The CLI also *offers* multi-year analytics views (`franchises`, `h2h`,
`records`), but the site deliberately does **not** consume them at build time.
Going-forward pattern: add a view to the CLI, then consider consuming it — but
don't make the CLI a **build-time** dependency without a strong reason. See
`ARCHITECTURE.md` → "The ESPN CLI".
